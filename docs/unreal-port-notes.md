# Porting notes: Unreal module → pure C++

Source of the port: `Source/Battlefield` (Unreal module, untouched by this work).
Target: `BattlefieldCpp/` (this folder). The goal was to keep the game logic **byte-for-byte identical in behaviour**
and change only what the engine used to provide.

## What replaced which Unreal facility

| Unreal | Pure C++ replacement |
|---|---|
| `CoreMinimal.h`, `int32`, `uint8`, `uint16`, `uint32` | `Platform/CoreTypes.h` (aliases of `<cstdint>` types + the standard headers the module relies on) |
| Module API macro `BATTLEFIELD_API` (generated by UBT) | defined in `Platform/CoreTypes.h` (`dllexport` / `dllimport` / `visibility`) |
| `UE_LOG(LogBattlefield, Error, TEXT(...))` | `BF_LOG(Error, "...")` → `FBattlefieldLog`; silent unless a sink is installed |
| `FName` (unit name in `FUnitData`) | `std::string` |
| `FVector`, `FUintVector`, `FMath::FloorToInt/IsNearlyEqual` | `Math/Vector.h` (`double` based, same field names) |
| `Battlefield.Build.cs` / UBT | `CMakeLists.txt` files (C++20, MSVC `/W4`) |
| `IMPLEMENT_MODULE`, `FBattlefieldModule` | not needed – the DLL is the module |
| `IMPLEMENT_SIMPLE_AUTOMATION_TEST`, `TestEqual`… | `BattlefieldTests/Private/Framework/AutomationShim.h` |
| Unreal automation runner / editor session | `BattlefieldTestRunner.exe` and the C API of `BattlefieldTests.dll` |

## File mapping

| Unreal (`Source/Battlefield`) | Pure C++ |
|---|---|
| `Public/Core/*`, `Public/Enums/*`, `Public/Events/*` and `Private/Core/*` | `Battlefield/Public|Private/Core|Enums|Events` — same file names |
| `UnrealClasses/GridMath.*` | `Math/GridMath.*` (without the Blueprint conversion helpers) |
| `UnrealClasses/BattlefieldLog.*` | `Platform/BattlefieldLog.*` (functional replacement, not a log category) |
| `Public/Tests/TestsHelper.h`, `Private/Tests/*Tests.cpp` | `BattlefieldTests/Private/Tests/*` |
| `Battlefield.h/.cpp` (module class) | dropped |
| `UnrealClasses/CombatStatsData`, `TurnResourceData`, `WeaponData` (DataTable rows), `GridCoord`, `TeamId`, `UnitMath` | dropped — these are Blueprint/DataTable wrappers (`USTRUCT`, `UENUM`) that only convert to and from the core types |
| Empty stub `.cpp` files (`Events/*.cpp`, `TeamSystemHelper.cpp`) | dropped (header-only types) |

The Unreal-side consumers (`Source/Hellmarch/.../BattlefieldSubsystem`, `BattlefieldQuerySubsystem`,
`BattlefieldGameMode`) are not part of this port. They keep using the original module; the DLL here is the
engine-independent twin that can be reused by tools, servers, simulators or other engines.

## Deliberate code changes (behaviour-neutral unless stated)

| # | Change | Why |
|---|---|---|
| 1 | `FGrid::MoveUnitToTile`: `assert(oldTile->actor == actor)` → `oldTile->unit` | The member `actor` does not exist; it only compiled in Unreal because `assert` was compiled out. |
| 2 | `FGrid::GetUnitPosition(nullptr)` returns `{-1,-1}` | The "not found" branch dereferenced the null pointer to log its team. |
| 3 | `FGrid::FGridCoordinate` members default to `0` | Default-constructed coordinates (e.g. in `FUnitData`) were uninitialised. |
| 4 | New `FTeamSystem::RemoveActor`; `FTroupe::DestroyActor` and `FTroupe::Clear` unregister units from the team system | The team system kept raw pointers to destroyed units (dangling after a failed spawn or `StartBattle`). Unit ids stay monotonic, so an id is never reused. |
| 5 | `BATTLEFIELD_API` added to `FTeamSystem`, `FTroupe`, `FBattlefieldData`, `FStatusEffect` | In Unreal the tests lived inside the module; across a DLL boundary these classes must be exported. |
| 6 | `inline` removed from private member declarations that are defined in the `.cpp` (`FGrid::GetTile`, `GetIndex`, …, `FBaseUnit::GetDistance`) | Exported classes should not declare out-of-line-defined members `inline`. They are still inlined by the optimiser. |
| 7 | `MAX_int16` → `INT16_MAX`; enum arguments of log calls cast to `int` | Unreal constant / printf correctness. |
| 8 | `TArray<FString>` → `std::vector<std::string>` in one test; `CreateTestEnemies` takes the controller by reference | The by-value version could never compile if called (the controller is not copyable). |

Everything else — formulas, event order, turn rotation, quirks — is unchanged. The known quirks are listed in
[gameplay-rules.md §10](gameplay-rules.md#10-known-placeholders-and-quirks-kept-from-the-unreal-module).

## Verification

* The 166 tests pass in Debug (asserts enabled) and Release.
* The harness was sanity-checked by temporarily breaking the turn rotation: three tests failed with readable
  messages and a non-zero exit code, and passed again after reverting.
* Not verified: behaviour inside Unreal itself is unchanged because that module was not modified; the DLL was
  built and tested on Windows x64 with MSVC 14.44 only. GCC/Clang builds are configured but were not run.
